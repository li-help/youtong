## 一、通用约定

### 1.1 请求地址
所有接口前缀为 `/api`，线上完整地址即以 `http://123.56.160.50/api` 为前缀。例如登录：`POST http://123.56.160.50/api/auth/login`。

> 注：线上当前为 HTTP（未配置 HTTPS 证书）。微信小程序、支付等场景需 HTTPS，正式上线请按 `deploy/README-DEPLOY.md` 第 4 节配置 certbot 证书，届时基地址改为 `https://<域名>/api`。

### 1.2 鉴权说明
后端通过 `JwtInterceptor` 拦截需鉴权的请求，放行规则（`WebMvcConfig`）如下：

- **白名单（无需 token）**：
  - `/api/auth/**`（登录 / 注册 / 微信 / 扫码登录等全部认证接口）
  - `/api/sync/**`（实时同步轮询与 SSE）
  - `/api/upload/**`（文件上传）
  - `OPTIONS` 请求、静态资源
- **需鉴权**：除上述外其余接口，请求头须携带：
  ```
  Authorization: Bearer <jwt-token>
  ```
- 未携带 / 过期 token 将返回 `R.fail("未登录或登录已过期")`。

### 1.3 统一返回结构 `R`
```json
{
  "code": 200,        // 业务状态码，200 成功，非 200 失败
  "msg": "ok",        // 提示信息
  "data": {}          // 业务数据
}
```

### 1.4 分页返回结构 `R.page`
列表类接口在 `data` 中返回分页对象：
```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "list": [],        // 当前页记录
    "total": 0,        // 总记录数
    "pageNum": 1,      // 当前页码
    "pageSize": 10     // 每页大小
  }
}
```

### 1.5 分页查询参数 `PageQuery`
列表接口接受 `PageQuery` 参数（query / body 均可），常用字段：
| 参数 | 类型 | 说明 |
|------|------|------|
| pageNum | int | 页码，默认 1 |
| pageSize | int | 每页大小，默认 10 |
|（实体字段）| any | 各业务实体字段均作为模糊/等值筛选条件透传 |

## 二、认证授权 `AuthController`（`/api/auth`）

> 本组全部接口免鉴权（白名单）。登录成功后返回 JWT，后续业务接口凭此 token 访问。

### 2.1 账号密码登录
`POST /api/auth/login`
```json
请求：{"username":"admin","password":"123456"}
响应：{
  "code":200,"msg":"ok",
  "data":{"token":"<jwt>","user":{"id":1,"username":"admin","nickname":"管理员","role":"admin"}}
}
```
失败返回 `用户名或密码错误` / `账号已被禁用`。

### 2.2 手机号 + 验证码登录（免密，自动注册）
`POST /api/auth/phoneLogin`
```json
请求：{"phone":"13800138000","code":"123456"}
响应：{"code":200,"data":{"token":"<jwt>","user":{...}}}
```
验证码错误返回 `验证码错误或已过期`；手机号格式错误返回 `请输入有效的手机号`。未注册用户会自动注册后登录。

### 2.3 注册
`POST /api/auth/register`
```json
请求：{"username":"13800138000","password":"123456","code":"123456"}
```
校验：手机号为合法 11 位、密码 ≥ 6 位、验证码正确、手机号未注册。成功返回 `注册成功`。

### 2.4 发送短信验证码
`POST /api/auth/sendCode`
```json
请求：{"phone":"13800138000"}
响应：{"code":200,"data":{"phone":"13800138000","code":"123456","demo":true,"expireSeconds":300}}
```
> 演示环境（`demo=true`）明文返回 `code`；正式环境经短信网关下发，`code` 为 `null`。

### 2.5 校验验证码
`POST /api/auth/checkCode`
```json
请求：{"phone":"13800138000","code":"123456"}
```
用于"忘记密码"流程第一步，验证通过返回 `R.ok()`。

### 2.6 验证码重置密码
`POST /api/auth/resetPwdByCode`
```json
请求：{"phone":"13800138000","code":"123456","newPassword":"123456"}
```
无需原密码，校验验证码后重置。新密码 ≥ 6 位。

### 2.7 原密码重置密码
`POST /api/auth/resetPwd`
```json
请求：{"username":"admin","oldPassword":"123456","newPassword":"654321"}
```
通过原密码校验后修改（账号密码登录场景）。

### 2.8 退出登录
`POST /api/auth/logout`
```json
响应：{"code":200,"msg":"ok"}
```
> JWT 为无状态令牌，服务端不维护会话，前端删除本地 token 即可。

### 2.9 微信小程序一键登录
`POST /api/auth/wechatLogin`
```json
请求：{"code":"<wx.login 返回的 code>"}
响应：{"code":200,"data":{"token":"<jwt>","user":{...}}}
```
后端用 `code` 调微信 `jscode2session` 换取 `openid`，按 openid 自动注册/登录。

### 2.10 微信扫码登录 —— 创建 ticket + 小程序码
`POST /api/auth/scanLogin/create`
```json
响应：{"code":200,"data":{"ticket":"<uuid>","expireSeconds":120,"qrcode":"/api/auth/scanLogin/wxacode/<ticket>"}}
```
微信配置异常时返回 `微信配置错误：...`。

### 2.11 微信扫码登录 —— 获取小程序码图片
`GET /api/auth/scanLogin/wxacode/{ticket}`
```
响应：image/jpeg（二进制 PNG 图片流）
```
失败（如 token 失效、页面未发布 41030）返回 HTTP 502 + JSON 错误信息。

### 2.12 微信扫码登录 —— PC 端轮询状态
`POST /api/auth/scanLogin/check`
```json
请求：{"ticket":"<ticket>"}
响应：{"code":200,"data":{"status":"waiting|scanned|confirmed|expired|not_found","token":"<confirmed 时附带>"}}
```

### 2.13 微信扫码登录 —— 标记已扫码
`POST /api/auth/scanLogin/marked`
```json
请求：{"ticket":"<ticket>"}
```
手机端进入确认页时调用，状态置为 `scanned`。二维码失效返回 `二维码已失效，请刷新重试`。

### 2.14 微信扫码登录 —— 确认登录
`POST /api/auth/scanLogin/confirm`
```json
请求：{"ticket":"<ticket>","code":"<wx.login code>"}
响应：{"code":200,"data":{"token":"<jwt>","user":{...}}}
```
手机端确认登录，底层按 openid 自动注册/登录并写入 ticket，PC 端轮询即得 token。

### 2.15 获取当前登录用户信息
`POST /api/auth/info`
```
请求头：Authorization: Bearer <jwt>
响应：{"code":200,"data":{"id":1,"username":"admin","nickname":"管理员","role":"admin"}}
```
> 注意：此接口虽在白名单组 `/api/auth` 下，但需前端携带有效 JWT 才能解析用户信息。

## 三、AI 智能助手 `AiController`（`/api/ai`）

> 基于 OpenAI 兼容协议调用大模型（配置项 `ai.base-url` / `ai.api-key` / `ai.model`）。
> 鉴权：继承通用规则，`/api/ai/**` 需 `Authorization: Bearer <token>`。

### 3.1 育儿问答
`POST /api/ai/chat`
```json
请求方式一（上下文数组）：
{"messages":[{"role":"user","content":"宝宝半夜哭闹怎么办？"}]}
请求方式二（单条消息）：
{"message":"宝宝半夜哭闹怎么办？"}
响应：{"code":200,"data":{"content":"<AI 回复文本>"}}
```
大模型不可用时返回 `AI 服务暂时不可用，请稍后再试`。

### 3.2 个性化推荐
`POST /api/ai/recommend`
```json
请求：{"age":"3","interests":["音乐","运动"]}
响应：{
  "code":200,
  "data":{
    "summary":"<AI 生成的 100 字内推荐导语>",
    "courses":[...],     // 热门课程（取前 4）
    "activities":[...],  // 热门活动（取前 3）
    "videos":[...]       // 热门视频（取前 3）
  }
}
```
`interests` 可为数组或逗号分隔字符串；AI 失败时降级为默认文案。

## 四、实时同步 `SyncController`（`/api/sync`）

> 用于跨端内容实时同步（C 端公开，白名单放行）。

### 4.1 查询频道版本号（轻量轮询）
`GET /api/sync/version?channel=xxx`
```json
响应：{"code":200,"data":<long 版本号>}
```

### 4.2 SSE 实时推送版本变化
`GET /api/sync/stream?channel=xxx`
```
响应类型：text/event-stream
事件格式：event: version\ndata: <版本号>\n\n
```
连接建立后立即推送当前版本号，后续频道版本变化实时推送；`channel` 缺失会抛参数异常。

## 五、通用 CRUD 业务接口（继承 `CrudController`）

以下业务实体 Controller 均继承 `CrudController<T>`，自动获得 7 个标准 RESTful 接口，仅路径前缀不同。

### 5.1 通用接口清单
以某资源路径前缀 `{base}` 为例（如 `/api/article`）：

| 方法 | 路径 | 说明 | 返回 |
|------|------|------|------|
| GET | `{base}` | 分页列表，接受 `PageQuery` | `R.page` |
| GET | `{base}/all` | 全量查询（不分页） | `R`（列表） |
| GET | `{base}/{id}` | 按主键查询详情 | `R`（实体） |
| POST | `{base}` | 新增记录 | `R` |
| PUT | `{base}` | 更新记录 | `R` |
| DELETE | `{base}/{id}` | 按主键删除 | `R` |
| POST | `{base}/batchDelete` | 批量删除（body 传 id 数组/列表） | `R` |

> 所有写操作（POST/PUT/DELETE）除 `/api/upload` 外均需 `Authorization: Bearer <token>`。

### 5.2 各业务实体路径映射
| 业务实体 | Controller | 路径前缀 |
|----------|-----------|----------|
| 文章 | `ArticleController` | `/api/article` |
| 活动 | `ActivityController` | `/api/activity` |
| 广告 | `AdController` | `/api/ad` |
| 广告位 | `AdPositionController` | `/api/ad-position` |
| 分类 | `CategoryController` | `/api/category` |
| 课程 | `CourseController` | `/api/course` |
| 收藏 | `FavoriteController` | `/api/favorite` |
| 订单 | `OrderController` | `/api/order` |
| 服务 | `ServiceController` | `/api/service` |
| 门店 | `StoreController` | `/api/store` |
| 用户地址 | `UserAddressController` | `/api/user-address` |
| 视频 | `VideoController` | `/api/video` |
| 系统账号 | `SysAccountController` | `/api/sys-account` |

### 5.3 示例
**分页查询文章**
```
GET /api/article?pageNum=1&pageSize=10
→ R.page：{ list:[...], total:23, pageNum:1, pageSize:10 }
```
**新增文章**
```
POST /api/article
Body: { "title":"...", "content":"...", ... }
```
**删除文章**
```
DELETE /api/article/12
```
**批量删除**
```
POST /api/article/batchDelete
Body: [12, 13, 14]
```

## 七、错误码与常见返回

| code | msg | 含义 |
|------|-----|------|
| 200 | ok | 成功 |
| 非 200 | 具体错误信息 | 业务失败（如 `用户名或密码错误`、`验证码错误或已过期`、`未登录或登录已过期` 等） |

> 部分微信相关接口（小程序码生成）在失败时直接返回 HTTP 502 及 JSON 错误体（`{"code":502,"msg":"..."}`），不经过 `R` 包装，前端需单独兼容。

## 八、调用示例（curl，线上环境）

```bash
# 线上基地址
BASE=http://123.56.160.50/api

# 1. 登录
curl -X POST $BASE/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}'

# 2. 携带 token 调用 AI 问答
curl -X POST $BASE/ai/chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <jwt>" \
  -d '{"message":"宝宝挑食怎么办？"}'

# 3. 查询课程列表（分页）
curl "$BASE/course?pageNum=1&pageSize=10" \
  -H "Authorization: Bearer <jwt>"

# 4. 轮询同步版本
curl "$BASE/sync/version?channel=home"
```
